## 0. 结论速览（TL;DR）

| 项 | 结论 |
|---|---|
| **主选** | **Godot 4.x（GDScript 作为 Web 导出语言）** |
| **备选** | **Cocos Creator 3.8 LTS（TypeScript）** |
| **排除** | Unity 6（WebGL）、Phaser 4（纯 Web 框架）、Unreal 5（Pixel Streaming） |
| **一句话理由** | 在"Web 优先 + 首包可控"硬约束下，Godot 4 同时覆盖四个候选玩法形态（2D 横版/卡牌/放置均一等公民，俯视角 ARPG 可走 3D 兼容管线），零授权/治理风险，Web 导出成熟（WASM 单线程默认、WebGL2、WebGPU 实验性），是唯一"2D 全能 + 3D 可选"且不牺牲 Web 体验的引擎。 |
| **最大风险** | Godot 4 的 Web 导出**仅支持 GDScript，不支持 C#**；团队若误以为可写 C# 上 Web，将造成返工。其次为移动端 iOS Safari 的 WASM/内存限制。 |

> 选型依据所有候选玩法形态（2D 横版 / 卡牌策略 / 放置修仙 / 俯视角 ARPG），**不等待策划线定稿**——本报告结论对四者均成立，仅实施细节不同。

## 1. 候选引擎清单与筛选标准

### 1.1 候选清单（5 个，覆盖"完整引擎"与"纯 Web 方案"两类）

| # | 候选 | 类型 | 版本基线（2026-08 核验） | 简述 |
|---|---|---|---|---|
| A | **Godot 4** | 开源完整引擎 | 4.4 稳定 / 4.5 beta（Web 导出 GDScript） | 免费 MIT，编辑器+场景+资源管线一体，2D 极强、3D 可承担，Web 导出成熟 |
| B | **Cocos Creator** | 商业免费引擎 | 3.8 LTS | 中国 Web/小游戏事实标准，TS 一等公民，包体极小，原生小游戏一键导出 |
| C | **Unity 6** | 商业引擎 | 6000.x LTS | WebGL 导出成熟但偏重，移动浏览器存在 WASM 函数数/内存硬伤 |
| D | **Phaser** | 纯 Web 2D 框架 | 3.90（最终版）/ 4 RC | 包体最小、迭代快，但仅 2D、无完整编辑器与资产管线、无原生/小游戏导出 |
| E | **Unreal 5** | 商业引擎 | 5.5+ | Web 仅 Pixel Streaming（服务端推流），非客户端导出，直接排除 |

> 事实核验来源：Godot 官方 Web 导出文档（C# 不可导出 Web，单线程默认）、Cocos Creator 3.8 LTS 社区/官方构建文档、Unity 官方（Runtime Fee 已取消；移动 WebGL 社区仍报 iOS Safari 问题）、Phaser 官方新闻（v3.90 为 v3 最终版，v4 处 RC）。**知识诚实声明**：Godot WebGPU 与 Phaser v4 均未正式 1.0，属"实验性/预发布"，本报告不把赌注押在其上。

### 1.2 筛选标准（从 GDD 硬约束 + 工程可辩护性推导）

1. **Web 导出成熟度**：浏览器优先为硬约束；必须产出标准 WASM/WebGL 构建，不依赖服务端推流。
2. **首包可控**：首屏加载（engine + 首场景）需在主流网络下 5~10 秒内可玩；长线内容走远程/分包。
3. **形态覆盖度**：必须覆盖四候选玩法形态（2D 横版/卡牌/放置/俯视角 ARPG），尤其 ARPG 是否可 3D。
4. **渲染管线 Web 适配**：WebGL2 为底线，WebGPU 为加分项（不押注）。
5. **资产管线与迭代效率**：有可视化编辑器 + 导入/图集/分包管线；适合内容量巨大的长线修仙题材。
6. **语言与团队上手**：中国团队人才池与学习成本（GDScript / TS / C# / JS）。
7. **社区生态**：中文资料、插件/商店、长期维护稳定性。
8. **授权与治理风险**：许可证、Runtime Fee、闭源锁定的可辩护性（Full 评审重点）。

## 2. 对比维度详表

评分口径：5 = 极佳，4 = 良好，3 = 可用但有明显代价，2 = 勉强，1 = 不可用。加权：Web 导出成熟度 ×0.25、首包体积 ×0.15、形态覆盖 ×0.15、Web 渲染适配 ×0.10、资产管线/迭代 ×0.10、语言上手 ×0.10、社区生态 ×0.08、授权治理 ×0.07（合计 1.00）。

| 维度 | 权重 | A. Godot 4 | B. Cocos 3.8 | C. Unity 6 | D. Phaser 4 | E. Unreal 5 |
|---|---|---|---|---|---|---|
| Web 导出成熟度 | 0.25 | 4（WASM 成熟，单线程默认免 COOP/COEP 头；GDScript only） | 4（Web/小游戏成熟，国内海量案例） | 3（可用但偏重，iOS Safari 有 WASM 函数数/内存硬伤） | 4（原生 Web 框架，但需手动适配小游戏） | 1（仅 Pixel Streaming 推流） |

| 语言与团队上手 | 0.10 | 4（GDScript 极易学；C# 可用于非 Web 端；国内人才池小于 C#/TS） | 4（TS 国内人才池大） | 5（C# 人才池最大） | 3.5（JS/TS 池大，但工程化需自建） | 2（C++ 门槛高） |
| 社区生态 | 0.08 | 3.5（全球增长快、中文资料渐多但少于 C/B） | 4.5（中文 Web/小游戏生态最强） | 4.5（全球最大） | 3（Web 2D 生态好，中文偏少） | 3（非 Web 场景） |
| 授权与治理风险 | 0.07 | 5（MIT，零费用零锁定） | 4（免费商用，引擎非完全开源） | 2.5（Runtime Fee 已取消但治理信任受损、闭源） | 5（MIT） | 2（授权费/分成复杂、闭源） |
| **加权总分** | **1.00** | **4.10** | **3.95** | **3.15** | **3.23** | **1.53** |
| 排名 | | **1** | **2** | 4 | 3 | 5 |

> 单项说明（可辩护依据）：
> - **Godot 4 Web 导出**：官方文档明确"Godot 4 项目用 C# 目前无法导出 Web"；4.3 起单线程导出为默认，无需 COOP/COEP 跨源隔离头，兼容 itch.io/主流发布渠道且对 macOS/iOS 更稳。WebGL2 为要求，WebGPU 实验性（4.3+）。→ 本项决定本项目 Web 端语言锁死为 **GDScript**。
> - **Unity 6 移动 WebGL**：官方承认移动端 WebGL 单线程、建议内存 <500MB；社区在 iOS 18.4 后大量上报低内存设备（≤3GB RAM）WASM 函数数 >10 万即崩溃。对"浏览器优先 + 多端"是实质风险。
> - **Cocos 3.8 LTS**：引擎裁剪后 ~1.5MB 级；主包控制靠远程资源 + 子包（微信主包 20MB/首包 4MB 经验），国内修仙/卡牌放置成熟度极高——这是它成为备选而非主选的核心原因。
> - **Phaser**：v3.90 是 v3 最终版，v4 仍 RC；无完整编辑器与资产管线，无原生小游戏导出；仅适合原型验证，不适合长线内容型项目。
> - **Unreal 5**：Web 只有 Pixel Streaming（云端渲染推流），不是客户端导出，直接排除。

## 3. 明确推荐

### 3.1 主选：Godot 4.x（GDScript）

**推荐理由（可辩护链）**：

1. **形态覆盖是本次选型的决定性变量**。策划尚未定稿，四候选形态中"俯视角 ARPG"是唯一可能需要 3D 的形态。Godot 4 是唯一在"2D 全形态一等公民 + 3D 可选（Compatibility 渲染器专为 Web 设计）"两点同时成立、且不牺牲 Web 体验的引擎。若最终定稿 2D（横版/卡牌/放置），Godot 4 2D 工具链（TileMap、CanvasItem、动画、UI）完全胜任；若定稿 3D ARPG，走 Compatibility 管线可落 Web，桌面/移动端可升级 Forward+。
2. **Web 导出成熟且首包可控**：WASM 单线程默认导出（4.3+），无跨源隔离部署负担；空包 gzip 约 10~15MB，配合资源分组（远程/分包）可把首屏压进可玩阈值。
3. **零授权/治理风险**：MIT 许可，无 Runtime Fee、无收入分成、无闭源锁定——在 Full 评审中是最强可辩护项，长线项目不会被商业条款绑架。
4. **资产管线数据驱动**：场景 .tscn 为文本可版本化，契合工作室"gameplay 数据驱动、core 零热路径分配"编码标准；编辑器内置导入/图集/动画/UI，满足长线内容量。
5. **迭代效率**：GDScript 学习曲线极低，策划/内容同学可读可改；热重载与场景编辑对"内容海量、频繁调参"的修仙题材极友好。

**取舍（诚实列出）**：
- 取：形态全兼容、Web 体验、零成本零风险、数据驱动。
- 舍：放弃"Web 端写 C#"（Godot 4 不支持）；放弃 Unity 级 3D 资产商店生态；中文人才池 < Cocos/Unity。
- 工程上：C# 仅限桌面/原生工具链（如服务端工具、离线批处理），Web 游戏逻辑统一 GDScript，规避双语言心智负担。

### 3.2 备选：Cocos Creator 3.8 LTS（TypeScript）

**何时启用备选（触发条件）**：
- 若 Phase 3 前策划线确认形态为 **纯 2D**（横版/卡牌/放置，排除 3D ARPG 诉求）；
- 且发行策略确定以**中国 Web 门户 + 微信/抖音小游戏为主**（遮天 IP 高概率）；
- 则切换到 Cocos：引擎 ~1.5MB、TS 人才池大、小游戏一键导出、国内同题材（修仙放置/卡牌）案例与素材生态最厚，风险更低、更快上市。

**备选代价**：3D/ARPG 能力弱于 Godot/Unity；编辑器闭源；长期自由改造受限。故仅作条件触发型备选，不作默认。

### 3.3 明确排除说明

- **Unity 6**：WebGL 移动端硬伤 + 首包偏重 + 授权治理信任受损，与"Web 优先"硬约束冲突。若未来项目转向"3D 重度 + 原生 App 优先"，可重新评估。
- **Phaser 4**：2D-only、无编辑器/资产管线、无原生小游戏导出，不适合长线内容型项目；保留为原型验证工具。
- **Unreal 5**：Web 仅推流，直接排除。

## 4. 已知风险与缓解（≥3）

### R1. Web 加载体验（首包与加载时长）
- 风险：Godot 空包 gzip 10~15MB，叠加首场景资源后，弱网/移动端首屏可能 >10 秒，流失率高。
- 缓解：
  1. 单线程导出 + Brotli/gzip 压缩（部署层），空包目标压进 ~10MB；
  2. 资源分组：引擎+首场景进首包，长线内容（地图、卡面、立绘、音效）进远程 Bundle 按需流式加载；
  3. 首屏"可玩优先"设计：加载界面进度 + 预加载关键资源，白屏即加载失败占位回退；
  4. CDN + 强缓存（哈希文件名），第二次访问接近秒开。

### R2. 移动端性能与内存（iOS Safari 为最弱端）
- 风险：iOS Safari WASM/WebGL 限制、内存沙盒（低端设备 ~1GB 上限）、上下文丢失；长在线放置/ARPG 常驻内存易 OOM。
- 缓解：
  1. 渲染走 Compatibility 管线，纹理压缩（WebP/ASTC/ETC2 按平台）、图集化、LOD；
  2. 建立性能预算（帧率/内存/显存）并在 Phase 3 落地 Profile 管线；低端设备测试矩阵（iOS 12/13、低内存安卓）；
  3. 对象池 + 定时 GC 触发窗口化，规避 GC 卡顿；长线会话定期重载场景回收内存；
  4. 监听 WebGL context lost 并实现自动恢复。

### R3. 长线内容量的资产膨胀
- 风险：修仙题材内容量大（境界、法宝、卡牌、地图、剧情），不控制则包体/加载失控、迭代变慢。
- 缓解：
  1. 数据驱动：数值/文案/配置走外部数据表（JSON/资源表），不入代码，支持热更；
  2. 模板复用 + 程序化生成（战斗特效、场景摆放），美术资产走图集/九宫格/合批；
  3. 建立内容管线（导入 → 校验 → 压缩 → 打包 → 版本化），自动化 CI 构建，阻断未优化资产入库；
  4. 分包/子包策略：功能模块（商城/背包/洞府）独立 Bundle 按需加载。

### R4. 语言约束：Godot 4 Web 不支持 C#（知识缺口，最易踩坑）
- 风险：团队惯性以为可写 C# 上 Web，Phase 3 后返工。
- 缓解：
  1. 立项即声明：Web 端游戏逻辑统一 GDScript；C# 仅限非 Web 工具/服务端；
  2. 若未来官方支持 C# Web 导出（跟踪 upstream），再评估迁移；不以此为前置依赖；
  3. 编码标准里明确"GDScript 为 Web 主语言"，招聘与培训同步。

### R5. 人才与生态
- 风险：国内 Godot 人才池小于 Cocos/Unity，中文资料少；引擎版本迭代快（4.4→4.5）。
- 缓解：
  1. 锁定版本（如 4.4 LTS 定位基线），核心 API 最小面，升级走 ADR 评审；
  2. 培训计划 + 关键岗位招聘倾斜；社区/官方文档中文化跟进；
  3. 风险对冲：保持 Cocos 备选评估持续更新，若团队上手显著受阻，Phase 3 前可切换（触发条件见 3.2）。

## 5. ADR 草案

### ADR-0001：引擎选型 —— Godot 4.x 为主选，Cocos Creator 3.8 为条件备选

- **状态**：Proposed（待主理人审批）
- **日期**：2026-08-06
- **决策者**：engineering-lead；审批：主理人（游承峰）

**背景（Context）**
- 新项目《遮天》：Web/多端、浏览器优先（硬约束），首包可控；
- 玩法形态未定稿（2D 横版 / 卡牌策略 / 放置修仙 / 俯视角 ARPG）；
- 用户明确要求工程侧给出推荐，评审强度 Full，决策需可辩护。

**备选方案（Considered Options）**
1. Godot 4.x（GDScript）—— 形态覆盖最全、Web 导出成熟、零授权风险；
2. Cocos Creator 3.8 LTS —— 中国 Web/小游戏生态最强、包体最小、TS 人才池大；
3. Unity 6 —— 3D 最强、全球生态最大，但移动 WebGL 硬伤 + 包体偏重 + 治理风险；
4. Phaser 4 —— 最轻量纯 Web，但 2D-only、无编辑器/资产管线；
5. Unreal 5 —— Web 仅 Pixel Streaming，排除。

**决策（Decision）**
- **主选 Godot 4.x**，Web 端语言锁 **GDScript**（Godot 4 官方不支持 C# Web 导出）；
- **条件备选 Cocos Creator 3.8 LTS**：若形态确认纯 2D 且中国 Web/小游戏为发行主渠道，切换至 Cocos；
- 排除 Unity 6 / Phaser 4 / Unreal 5（理由见 §3.3）。

**后果（Consequences）**
- 正面：形态全兼容、Web 首包可控、零授权成本、数据驱动契合内容量需求、开源可长期维护；
- 负面/代价：
  1. Web 端放弃 C#；团队需适应 GDScript；
  2. 3D 能力上限低于 Unity（但满足 ARPG 需求基线）；
  3. 中文人才池与资料较少，需培训与招聘倾斜；
  4. 引擎版本迭代快，需版本锁定与 ADR 治理。
- 触发备选的条件与退出机制已定义（§3.2），Phase 3 前若满足触发条件即走 ADR 修订流程。

**评审记录**
