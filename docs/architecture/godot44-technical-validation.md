## 1. 验证范围与验收口径

对齐美术圣经 v0.2 §8.4 定稿口径，并裁决一处**跨线预算冲突**（见 §5.1）：

- 首屏可玩 <5MB：指「引擎壳加载完成 + 首屏美术就绪」所需**美术资源增量** ≤5MB；
- 引擎 + 首场景 <10MB：指「引擎壳 + 首场景全部资产」总下载（gzip/Brotli 传输口径）；
- 远程 Bundle 流式：长线内容按区域/玩法打包，每个 Bundle ≤3MB；
- 移动端 2019 中端机（骁龙 730 / iOS A13 同等）30fps 稳定。

**冲突点**：美术圣经 §8.4 同时写了「引擎壳 gzip 10~15MB（不计入首屏美术配额）」与「引擎+首场景 <10MB」——若引擎壳实测真的落在 10~15MB，则 <10MB 总口径在数学上不可能达成。工程侧裁决见 §5.1。

### 2.2 目标与门禁（非实测，待校准）

| 口径 | 目标值 | 硬门禁 | 超限动作 |
|---|---|---|---|
| 引擎壳 gzip（单线程） | ≤9MB | 12MB | 触发预算评审：裁剪引擎功能 / 上修总口径 / 重排首屏 |

- **引用来源**：Godot 4.x Web 导出采用 WASM（WebGL2 要求）；官方文档确认单线程导出（4.3+ 默认）为更小且免跨源隔离头的最稳方案。空包绝对数值随版本/功能裁剪浮动，社区讨论常见 10~15MB gzip 量级——**一律以本地实测为准**。

### 2.3 预计影响

- 若引擎壳实测 ≤9MB：美术首屏配额 ≤5MB 可让「引擎+首场景 <10MB」成立，全口径沿用。

- 若引擎壳实测 >12MB：必须裁剪（3D 模块本作 MVP 不用可裁）、或评估单线程最小导出、或重议「<10MB」口径。本作 MVP 为 2D 主导（概念文档红线排除重度 3D/实时动作），裁剪空间充足。

## 3. 验证项 2：单线程导出部署头

### 3.1 结论（官方文档确认，待本地复验）

- **单线程导出（4.3+ 默认，本项目采用）：无需 COOP/COEP 跨源隔离头**，无需 SharedArrayBuffer，对 itch.io / 普通静态托管 / CDN 均友好；macOS/iOS Safari 兼容性更稳。
- **多线程导出：需要 COOP/COEP 响应头 + 跨源隔离环境**（意味着宿主页不能混第三方广告/外部脚本，部署约束大）——本项目**默认不采用**。

### 3.2 待实测清单

| # | 步骤 | 通过判据 |
|---|---|---|
| 1 | 单线程导出后，本地静态服务器（无任何 COOP/COEP 头）打开 | Chrome/Edge/Firefox 正常启动游戏 |
| 2 | iOS Safari（≥15）与 Android Chrome 打开 | 正常启动（单线程对 iOS 更稳） |
| 3 | 若未来必须多线程：配置 `Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp` | 单独验证，不进 MVP 默认 |

### 3.3 预计影响

- 部署极简：任意静态托管/CDN 即可，无特殊头配置 → CI 与发布成本低。

## 4. 验证项 3/4：纹理压缩与 WebGL2 基线

### 4.1 纹理压缩（Godot 4.4 导入机制）

- **源图格式**：Godot 4.x 导入器支持 WebP（有损/无损）作为源图；美术圣经 §8.1 已定源图 WebP 为主。
- **平台 VRAM 压缩**：Godot 导入选项「VRAM Compressed」按目标平台产出变体——桌面/Web 用 S3TC/DXT，移动端用 ETC2 / ASTC；Web 导出按浏览器能力选变体。透明图优先 WebP 通道。
- **待实测细节**：4.4 导入器 UI 的具体选项路径、Web 平台默认变体选择、ASTC 在 WebGL2 浏览器的实际支持矩阵（Chrome/Android 支持较好，iOS Safari 的 ASTC 支持需真机验证）。
- **决策门（已与 art-director 对齐）**：若 iOS Safari 真机 ASTC 不理想 → 移动端降级档切 **ETC2**（美术圣经 §8.1 已同意，无需改规格，仅换压缩变体选型）。

### 4.2 WebGL2 基线

- Godot 4 Web 导出**硬性要求 WebGL2**（官方文档）；WebGPU 为实验性（4.3+），**不押注**。
- 移动端 2019 中端机（骁龙 730 GPU Adreno 618 / A13）均支持 WebGL2 → 可覆盖美术圣经基准机。
- 待实测：真机矩阵（iOS Safari / Android Chrome 低端机）跑首场景 Profile，确认 30fps + 无 context lost。
- **联动门（已与 art-director 对齐）**：首场景 30fps Profile 若需美术配合降档（粒子减半/关闭实时阴影/低画质开关），由 art-director 按美术圣经 §8.5 执行，工程侧提供 Profile 数据与判定标准。

### 4.3 预计影响

- 纹理规格按美术圣经 §8.1 执行（2048² 上限 / 1024² 移动降级档 / UI 图集 ≤2048²×2）即可满足 WebGL2 基线；无需因引擎改规格。

## 5. 验证项 5：资源分组 / 远程 Bundle + 首包配额共享预算表

### 5.1 口径裁决（关键：解决美术圣经内部冲突）

美术圣经 §8.4 同时要求「引擎壳 gzip 10~15MB 不计入首屏美术配额」与「引擎+首场景 <10MB」。**数学上冲突**。工程裁决：

> **采用「分阶段加载预算」模型，将「首屏可玩」定义为阶段 1 而非阶段 0：**
>
> - **阶段 0 · 引擎壳**：仅引擎 WASM + 引导壳（loading UI）。目标 gzip ≤9MB（硬门禁 12MB）。
> - **阶段 1 · 首屏可玩**：引擎壳 + 首屏美术（标题场景 + 荒古禁地新手区低模档 + UI 核心 + 字体子集）。**总下载目标 ≤10MB**；其中**美术增量配额 ≤5MB**（对齐「首屏可玩 <5MB」口径）。
> - **阶段 2 · 长线流式**：远程 Bundle（每 ≤3MB），区域/玩法按需加载。
>
> **触发评审的条件**：若阶段 0 引擎壳实测 gzip >8MB，则「阶段 1 ≤10MB」自动上修为「≤ 引擎壳实测 + 首屏美术 ≤5MB」并**同步 art-director 与策划线口径**（预计 ≤14MB）。此裁决避免"死守 10MB 却无法达成"的假预算。

### 5.2 引擎壳 vs 美术资源 首包配额共享预算表（供美术线引用）

| 预算项 | 配额（目标） | 硬门禁 | 归属 | 说明 |
|---|---|---|---|---|
| 引擎壳 gzip（单线程） | ≤9MB | 12MB | 工程 | 空包 + 引导壳；本作 MVP 裁剪 3D/未用模块 |
| 首屏美术增量（阶段 1 增量） | **≤5MB** | 6MB | 美术 | 标题场景 + 新手区低模 + UI 核心 + 字体子集（字体 ≤2MB 内，见美术圣经 §6.3） |
| 阶段 1 总下载 | ≤10MB | 14MB | 共享 | 引擎壳 + 首屏美术；超 8MB 引擎壳即触发口径上修 |
| 远程 Bundle | 每 ≤3MB | 3MB | 美术+工程 | 按区域/玩法分包；命名 `区域_类型_名称` |
| 全局去重 | — | — | 共享 | 共享图集/粒子/字体子集；首包与远程 Bundle 禁重复引用同一贴图（美术圣经 §8.4） |
| 移动端基准 | 30fps | 30fps | 共享 | 2019 中端机；低端档降级方案按美术圣经 §8.5 |

### 5.3 远程 Bundle 实现路径（Godot 4.4）

- 机制：`ResourceLoader.load("res://...")` 走本地；远程 Bundle 用 `HTTPRequest`/`ResourceLoader` 加载外部 `.pck`（PackedScene/资源包）后按需实例化。
- MVP 落地路径：首包只含阶段 1 资源；荒古禁地后续区域、卡面图鉴、名场面档案、活动内容全部打远程 Bundle。
- 待实测：.pck 远程加载的缓存/失败回退/版本管理；CI 打包 Bundle 并生成清单。
