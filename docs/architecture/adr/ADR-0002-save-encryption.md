# ADR-0002：存档加密与数据模型（user:// 管理、版本迁移）

- 状态：Proposed（待主理人审批）
- 日期：2026-08-06
- 决策者：engineering-lead；审批：主理人（游承峰）
- 关联：ARCH-ENG-006 §2.4 / §3.9；ARCH-ENG-003 §4（存档）

---

## 背景（Context）

《遮天》为 Web 在线游戏，**服务端权威**（ADR-0003）。但客户端仍需本地缓存存档（离线可读、弱网容错、减少拉全量）。Godot Web 存档路径为 `user://`（浏览器 IndexedDB 抽象），存在两类风险：
1. **篡改风险**：客户端本地数据可被 DevTools/脚本修改，若服务端不校验将导致数值作弊；
2. **升级风险**：版本迭代后存档结构变化，无迁移机制会导致读档崩溃或数据丢失。

## 备选方案（Considered Options）

1. **客户端零存档（纯服务端）**：每次登录全量拉取，不落本地。→ 弱网体验差、白屏期长，违背 P3"即开即玩"。
2. **明文 JSON 落盘**：user:// 直接存明文。→ 可读可改，配合服务端校验勉强可用，但泄露结构、易被注入。
3. **加密 + 签名 + 版本迁移（选定）**：user:// 存加密载荷（含校验签名），服务端为准、客户端为缓存；升级走版本迁移。

## 决策（Decision）

- **客户端存档 = 服务端权威存档的加密缓存**，仅用于离线展示/弱网容错，**不信任其数值**（一切结算走服务端，ADR-0003）。
- 存储格式：JSON 序列化 → 加密（对称密钥按发布渠道分发，如 AES-GCM，密钥混淆不追求绝对安全——目标防"随手改"，不防逆向）→ user:// 写盘；载荷内含 `checksum`（对关键字段签名），读档校验失败即回退默认档并提示。
- **数据模型**：统一 `SaveModel`（ARCH-ENG-006 §3.9），顶层含 `version`；`SaveManager.load_save()` 读取后调用 `migrate_if_needed(raw)`。
- **版本迁移**：`version` 递增，迁移函数表 `{from_version: func}` 顺序执行；迁移失败回退旧档备份（`save.bak`），不静默丢档。
- 服务端下发完整权威存档时覆盖本地缓存（哈希比对防篡改回写）。

## 后果（Consequences）

- 正面：弱网可读、升级不崩、基础防篡改；`SaveModel` 单模型让核心层可 headless 单测。
- 代价：加密非绝对安全（防君子不防逆向）；需维护迁移链；`user://` 在部分浏览器有容量/清理策略差异（待实测）。
- 触发修订：若发现客户端篡改可影响服务端结算 → 提升为"客户端零信任 + 全量服务端校验"（ADR-0003 已覆盖结算侧）。
