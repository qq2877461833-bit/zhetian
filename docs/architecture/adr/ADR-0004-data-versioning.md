# ADR-0004：数据表版本管理（JSON Schema + CI 校验 + 热更路径）

- 状态：Proposed（待主理人审批）
- 日期：2026-08-06
- 决策者：engineering-lead；审批：主理人（游承峰）
- 关联：ARCH-ENG-004 §2（数据驱动约定）；ARCH-ENG-005 §2（CI 门禁）；ARCH-ENG-006 §5（Schema 草案）

---

## 背景（Context）

《遮天》全部数值以 JSON 数据表驱动（境界/角色/战斗/掉落/抽卡），策划迭代频繁、长线热更需求明确（活动、平衡调整）。风险：
1. 数据表字段变更（增/删/改名）导致运行时解析崩溃或静默错误；
2. 多表交叉引用（如 battle.json 引用角色 class、drop.json 引用境界 id）无校验，改一漏一；
3. 热更上线旧表覆盖新表 → 版本错乱。

## 备选方案（Considered Options）

1. **无版本管理（明文表直接读）**：→ 迭代期可用，上线后热更必出事，否决。
2. **仅 CI 校验 + 固定表名**：校验通过即发布，但无热更版本追踪。→ 部分满足，仍缺运行时版本一致性。
3. **Schema 版本 + 引用完整性 + CI 门禁 + 热更清单（选定）**：每表 `schema_version`；跨表引用用 id 注册表校验；CI 强制；热更带版本与兼容性检查。

## 决策（Decision）

- **每表 Schema 版本化**：所有 `data/tables/*.json` 顶层含 `schema_version`（正整数）；运行时加载器校验版本，不匹配拒绝加载（fail-fast，不静默）。
- **引用完整性校验（CI 必跑）**：统一 id 注册表（角色 id / 境界 id / 职业 id / 道具 type），跨表引用必须命中注册表；CI 脚本（ARCH-ENG-005 §2）在构建前执行，失败即阻断。
- **字段类型校验**：Schema 描述字段类型/必填/范围；加载器生成类型化访问（或校验层），杜绝"字段改名静默变 null"。
- **热更路径**：数据表独立于代码打包（可远程 Bundle/资源表更新）；热更包携带 `table_version` + 变更摘要；客户端加载时对比本地版本，仅接受兼容升级（向前兼容策略：只增不删字段、改名走别名迁移）。
- **禁止硬编码**：代码零 magic number；一切数值经数据表（ARCH-ENG-004 §2 延续）。

## 后果（Consequences）

- 正面：迭代与热更安全；跨表引用错位在 CI 即暴露；运行时 fail-fast 避免线上静默事故。
- 代价：Schema 维护成本（策划改表需同步 Schema）；热更兼容策略约束"只增不删"（需与策划线约定）；加载器多一层校验开销（一次性，可忽略）。
- 触发修订：若热更需求出现破坏性变更（删字段/重构），升级流程须走"迁移 + 双版本兼容窗口"，另行评审。
