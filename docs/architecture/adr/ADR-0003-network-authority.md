# ADR-0003：网络权威模型（服务端验证，客户端只读）

- 状态：Accepted（评审 PASS · 项目方拍板）
- 日期：2026-08-06（V1.1：服务端复用定案更新）
- 决策者：engineering-lead；审批：主理人（游承峰）
- 关联：ARCH-ENG-006 §7（八项防篡改点）；ADR-0002（本地存档仅缓存）；GDD-002/003/004/005（抽卡/战斗/掉落/帝路）

---

## 背景（Context）

《遮天》是带经济与竞争的 Web 放置游戏：抽卡、战斗、掉落、离线收益、帝路段位都涉及**资源/进度改变**。Web 客户端完全暴露于用户（DevTools 可改内存/请求/存档），若任何结算信任客户端，将出现：刷资源、改概率、改离线时长、伪造帝路胜场——直接击穿 GDD-002 G4（保底公开）、GDD-001 G4（防通胀）、GDD-005 §7（防守门员）等红线。

## 备选方案（Considered Options）

1. **纯客户端结算 + 服务端记账**：客户端算结果、服务端只存。→ 完全不防篡改，否决。
2. **服务端校验 + 客户端预演**（选定）：服务端为唯一权威，客户端仅上报意图与展示结果。→ 防篡改最彻底，代价是服务端实现量增加。
3. **混合（部分系统客户端）**：纯表现类（演出、UI 状态）客户端自治；一切改数值/进度动作服务端权威。→ 实为方案 2 的细化，采纳其边界。

## 决策（Decision）

- **服务端权威（Server-Authoritative）**：所有改变"数值/进度/资源/竞争结果"的动作，由服务端确定性结算后回写；客户端只读展示。
- **八项防篡改点**（ARCH-ENG-006 §7）：①战斗结算 ②掉落 ③抽卡保底 ④离线结算 ⑤帝路镜像 ⑥大境界等待计时 ⑦体力恢复/每日重置 ⑧源石供给预算——全部服务端权威。
- **客户端职责**：输入意图上报（NetManager.request）+ 演出播放（BattleResult 快照）+ 只读视图（SaveModel 只读接口）。
- **幂等**：所有写 API 幂等（客户端重试不产生重复结算）；请求带 `request_id`，服务端去重。
- **时间**：结算一律用服务端时间（TimeService），客户端时间不可信（防系统回拨刷离线收益）。
- **实现一致性（定案）**：核心层 8 服务（ARCH-ENG-006 §3）作为结算逻辑**唯一实现**；**服务端复用同份 GDScript 代码**（项目方拍板），杜绝"两端各一套公式"的口径漂移。服务端运行形态（Godot 无头 / GDScript 托管）留待 Phase 4 技术验证确定。

## 后果（Consequences）

- 正面：防篡改闭环满足经济/竞争红线；核心层纯逻辑天然可单测（同一份代码服务端与 CI 共用）；客户端包体轻（无结算逻辑）。
- 代价：服务端成为强依赖（登录即联网，离线仅可读缓存——与 P3"片刻亦修仙"兼容：离线收益在服务端结算，回归即领）；服务端实现/部署成本增加；需协议版本化与幂等治理。
- 风险缓解：MVP 服务端范围收敛到八项防篡改点 + 账号/存档，不铺全后端；架构为后续扩展留接口。
