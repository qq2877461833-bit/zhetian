## 0. 分层总原则

> **依赖单向**：玩法层 → 核心层 → 基础层。禁止反向依赖、禁止跨层直连（玩法不得 import 基础层实现，核心层不得依赖任何渲染/引擎壳）。
>
> 目标：核心层**纯逻辑可 headless 单测**（不依赖 Godot 渲染树）；玩法层可快速替换（UI/演出不影响数值与存档）；基础层可独立演进（引擎/网络/存档/CI 升级不波及上层）。

---

## 1. 三层划分

### 1.1 基础层（Foundation）——"引擎壳 + 平台适配"

职责：引擎初始化、引导加载、平台能力、网络传输、存档持久化、资源管理（首包/远程 Bundle）、遥测。

| 模块 | 说明 | 示例（Godot） |
|---|---|---|
| Bootstrap | 启动流程、加载阶段机（阶段 0 引擎壳 → 阶段 1 首屏 → 阶段 2 流式） | `Autoload:Bootstrapper` |
| 资源管理 | 首包/远程 Bundle 加载、失败回退、版本清单 | `ResourceLoader` + `HTTPRequest` |
| 网络层 | HTTP/WebSocket 传输、协议编解码、超时重试 | `HTTPRequest` 封装 |
| 存档 | 存档加密、版本迁移、user:// 管理 | `FileAccess` + 加密（详见 ADR-待立） |
| 遥测 | 事件上报、A/B 标识 | 自研轻量 + 服务端 |

- **约束**：基础层不得引用玩法/核心业务语义（不许 import 卡牌/境界相关）；只提供通用能力接口。

### 1.2 核心层（Core）——"数值与规则引擎"

职责：全部**纯逻辑**业务规则，不依赖渲染：数值/经济引擎、境界、放置收益、养成、战斗结算、抽卡概率、帝路镜像结算、存档数据模型。

| 模块 | 说明 | 形态 |
|---|---|---|
| 数值引擎 | 属性公式、成长曲线、边际收益递减 | `RefCounted` 纯类 |
| 经济引擎 | 源石/灵石双币、产出/消耗、离线收益上限 12h | 纯类 + 数据表驱动 |
| 境界系统 | 轮海→道宫→四极→化龙→仙台（MVP 前两境完整，框架预留） | 状态机 + 数据表 |
| 养成系统 | 等级/突破/法宝/功法 | 纯类 |
| 战斗结算器 | 布阵 + 自动战斗（回合/半即时）结算 | 纯类（可 headless 验证） |
| 抽卡/保底 | 概率 + 保底 + 事件化获取 | 纯类 + 数据表 |
| 帝路竞技 | 异步镜像结算、段位 | 纯类 + 网络层调用 |

- **约束**：核心层**零渲染依赖**；所有数值来自数据表（JSON），不入代码；可 100% 单测。

### 1.3 玩法层（Gameplay）——"场景与表现"

职责：UI、场景、战斗演出、新手区、名场面档案、卡面图鉴、开场演出（九龙拉棺）等一切"看得见"的部分；只做**编排与表现**，不持有数值规则。

| 模块 | 说明 |
|---|---|
| UI | 卷轴/符箓/铭文母题；状态由核心层暴露的只读视图驱动 |
| 场景 | 荒古禁地新手区、主城/界面场景（TileMapLayer / Control） |
| 战斗演出 | 读核心层结算结果 → 播动画/粒子/文本 |
| 演出 | 突破演出、九龙拉棺开场、帝路晋升 |
| 图鉴/档案 | 卡面 + 名场面档案浏览（远程 Bundle 内容） |

- **约束**：玩法层**不持有游戏状态**（数值/进度只读核心层）；UI 不得直接改存档（经核心层 API）。

## 2. 数据驱动约定

1. **数值表一律 JSON，不入代码**：境界参数、角色属性、掉落、概率、文本均进数据表；代码只读表。
2. **Schema 先行**：每个数据表有 JSON Schema（或类型化加载器），CI 校验（字段缺失/类型错即失败）。
3. **命名约定**：`res://data/tables/xxx.json`；按系统分文件（`realm.json`、`character.json`、`battle.json`…）。
4. **热更友好**：数据表独立于代码打包，支持远程更新（阶段 2 起）。
5. **禁止硬编码数值**：任何 magic number 视为缺陷；常量表放 `data/tables/constants.json`。

## 3. Web 端 GDScript 编码标准（草案，Phase 3 细化）

1. **语言**：全部 GDScript（Web 端）；C# 仅限非 Web 工具（见 ARCH-ENG-003）。
2. **类型标注**：公共 API 全量类型标注（`-> void`、参数类型）；减少动态分派对性能与可读性双利。
3. **单例白名单**：`Autoload` 仅限基础层（`Bootstrapper`、`SaveManager`、`NetManager`、`ResourceManager`）；核心/玩法层禁止全局单例滥用，用显式依赖注入。
4. **信号优先**：跨层通知用 Signal，禁止轮询、禁止 `get_node` 链式深访。
5. **热路径约束**：帧循环（`_process`/`_physics_process`）内禁字符串拼接、禁 `load()`、禁隐式 GC 分配；对象池化粒子/弹字。
6. **错误处理**：资源/网络加载一律显式错误分支 + 回退；禁静默吞错。
7. **命名**：文件 snake_case；类 PascalCase；常量 UPPER_SNAKE；资源路径 `res://` 绝对路径。
8. **注释语言**：中文注释（面向国内团队），关键决策引用 GDD 需求 ID / ADR 编号。

## 4. 性能预算条目（草案，对齐美术圣经）

| 预算 | 目标 | 硬门禁 | 备注 |
|---|---|---|---|
| 帧率 | 2019 中端机 30fps | 30fps | 移动低端档按美术圣经 §8.5 降级 |
| 单场景活跃粒子 | 桌面 ≤2000 / 移动 ≤800 | — | 美术圣经 §7.3 |
| 首屏可玩 | 美术增量 ≤5MB | 6MB | ARCH-ENG-002 §5 |
| 引擎+首场景 | ≤10MB | 14MB（引擎壳>8MB 触发口径上修） | ARCH-ENG-002 §5 |
| 远程 Bundle | 每 ≤3MB | 3MB | 区域/玩法分包 |
| 纹理 | ≤2048² | — | 移动降级 1024²（美术圣经 §8.1） |
| Shader | 3 套通用 | Variant ≤24 | 美术圣经 §8.3 |
| 内存 | 长在线会话可回收 | 无 OOM | 对象池 + 定期回收 |

> 预算条目在 Phase 3 主架构中落为可执行 Profile 清单（帧率/内存/包体三线门禁，CI 自动上报）。

## 5. 测试与可验证性

- **核心层**：纯逻辑类 headless 单测（GDScript 测试框架，如 GUT）；CI 必跑。
- **基础层**：网络/存档 mock 化测试；远程 Bundle 回退测试。
- **玩法层**：场景冒烟测试（加载即通过）+ 关键演出无崩溃；人工 QA 由严守真负责执行，工程侧提供可测试接口与日志埋点。
- **验收证据**：每个 Story 附测试证据路径（如 `tests/core/test_battle.gd` 运行结果）。
